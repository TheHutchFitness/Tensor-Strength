# RCA — `/public` assets 404 in production (tensorstrength.com)

## Summary
Your suspected root cause is **correct in mechanism, with one important refinement**: the production image is running the Next.js **standalone** server (`node server.js`), and the `public/` folder is **not present next to `server.js`**, so every `/public` asset 404s. However `.next/static` **IS** being served correctly, so the fix is narrower than "copy public/ AND .next/static" — only `public/` is missing.

## Evidence (from the live deployment, active run `88376a1a-1f69-4955-bd90-69081d11d458`)
Live probes against `https://trainer-profiles-2.emergent.host` (same runtime behind tensorstrength.com):
- `GET /tensor-strength-logo.jpg` → **404** (body = Next.js's own "404: This page could not be found." HTML)
- `GET /videos/coach.mp4` → **404** (same Next.js 404 page)
- `GET /` → **200**, fully styled
- The rendered HTML pulls `/_next/static/css/...css` and `/_next/static/chunks/*.js` and the page is styled → **`.next/static` is served fine (200).**

Runtime logs (active run pod):
```
Starting Next.js app: node server.js in /app
▲ Next.js 15.5.18
✓ Ready
```
→ The container runs the **standalone server** (`node server.js`), not `next start`.

Template: `nextjs_mongo_shadcn_base_image` (`next` family), `frontend_type: kubernetes` — Next.js serves directly on port 3000, **nginx is disabled** for this template. There are **no deployment manifest overrides** in GCS, so the platform's built-in `next` Dockerfile is in effect.

## Answers to your three questions
1. **Is `public/` in the runtime next to `server.js`, and do the requests 200/404?**
   Both assets return **404**. `public/` is NOT alongside the standalone `server.js`. In contrast `.next/static` IS present (CSS/JS 200). So the built image copies `.next/static` into the standalone output but **not** `public/` — exactly the standalone gotcha you described, but affecting `public/` only.

2. **Copy `public/` into standalone, or drop `output: 'standalone'`?**
   **Do NOT drop `output: 'standalone'`.** This platform's `next` template entrypoint hard-runs `node server.js`, and `server.js` only exists when standalone output is enabled. Removing standalone would leave no `server.js` and break the container boot. → The correct fix is to get `public/` **into the standalone output** so the Docker `COPY .next/standalone ./` picks it up.

3. **Ingress/CDN body-size limit on the 3.6 MB video?**
   **Ruled out.** The 81 KB logo 404s with the identical Next.js 404 page, and the 404 is the app's own 404 (not an ingress/CDN error page). A size cap would not 404 the tiny logo, nor return the Next 404 HTML. This is 100% the public-folder issue, not a size limit. (Latest build diagnosed — the current image is the 3.6 MB version.)

## Fix (source-side, no pipeline change needed) — VERIFICATION NOTE
> I could NOT reproduce this in the eph sandbox — the sandbox pod repeatedly failed to start (platform infra error: "pod reached terminal phase Failed before becoming Running"). The diagnosis above is therefore evidence-based (live probes + runtime logs), not eph-reproduced. The fix below is the canonical Next.js standalone remedy and matches the exact observed symptom.

Add a `postbuild` script to **`package.json`** so `public/` is copied into the standalone output right after `next build` (npm/yarn run `postbuild` automatically after `build`, which the platform Dockerfile invokes):

```json
{
  "scripts": {
    "build": "next build",
    "postbuild": "cp -r public .next/standalone/public"
  }
}
```

Why this works: the platform Dockerfile does `COPY .next/standalone ./` → `/app`. Placing `public/` inside `.next/standalone/` at build time makes it land at `/app/public`, next to `server.js`, where the standalone server serves it at the web root. `.next/static` already works, so it needs no change (leave it alone).

If `.next/standalone` doesn't exist at postbuild time in your environment, guard it:
```json
"postbuild": "cp -r public .next/standalone/ 2>/dev/null || true"
```
(but since `output: 'standalone'` is set, `.next/standalone` will exist after build).

## After applying
Redeploy. Then re-probe `/tensor-strength-logo.jpg` and `/videos/coach.mp4` — both should return 200. Keep `output: 'standalone'` as-is.
